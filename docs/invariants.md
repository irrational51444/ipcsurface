# 不变量（Invariants）

这份文件回答一个问题：这个工具的「特色」哪些是写死在代码/自检里的契约，
哪些还是作者自觉。路线图（目标.docx）P0 第 3 条点破过——特色是作者风格，不是契约。
下面是五条不变量，每一条都要能被 `scripts/selfcheck.py` 咬住：改坏了，CI 就红。

## I1 · 默认路径永远零依赖、一条命令可用

- **是什么**：`ipcsurface.py` 和它 import 的产品模块，只能用标准库。装一个 Python
  就能跑，不 `pip install` 任何东西。
- **为什么**：入口条件。曾踩过坑——打包清单漏模块、装完悄悄降级（见 0.83.0）。
  零依赖是这条的底线，不该因为「顺手加个库」就破。
- **怎么守**：selfcheck 扫全部产品模块的 import，凡是不在标准库清单里的都算红。
- **允许**：`ipcsurface[precise]`（路线图 P1-7 的双引擎）是 opt-in，不在默认路径内。

## I2 · 每条通道结论必须带 evidence + strength + refutes_if

- **是什么**：报告里每一条通道，JSON 层都必须带三个字段：
  `refutes_if`（什么情况说明这条结论是错的）、`strength`（证据强度，数字）、
  `sources`（这条结论从哪来）。缺一个就是坏结论。
- **为什么**：拒绝下结论、把「能信多少」做成结构化，是这个工具的内核。三条里
  尤其是 `refutes_if`——它逼着每条结论自己写「我可能错在哪」。
- **怎么守**：selfcheck 拿一个真包跑出 JSON，断言 evidence 里每个通道都有
  `refutes_if` 和 `strength`，且 `strength` 是数值不是空串。
- **注意**：schema 版本号变了要同步（现在 `ipcsurface/asar/17`），这也是自检在守的。

## I3 · 未知写 null，0 只许表示「确认没有」

- **是什么**：三态要分清楚——`null` = 没查到 / 不适用；`0` = 确认是零个；
  空字符串 `""` = 数据坏了，不允许出现在结论字段里。
- **为什么**：混淆这三态是静默撒谎。`0` 条通道和「没跑」是两码事；历史上有过
  「两列都为空」被读成「没有通道」的教训。
- **怎么守**：schema 层强制（结论字段的类型），selfcheck 抽查证据字段里没有
  `""` 冒充 null。更严的「0 语义」逐字段校验随语料库（I4）一起上。

## I4 · 报告分三层，md 和 JSON 都要全，不许静默丢产出

- **是什么**：一份扫描的产出分三层，各司其职：
  - **摘要**（`--summary`）：一页纸，只给计数和几个样本，给人快速判断。**还没实现。**
  - **全量 md**（默认）：每条结论一行，带档位 / 位置 / 跳数 / 经过。人读的全量。
  - **JSON**（`--format json`）：机器读的全量，字段比 md 多。
- **为什么**：一页纸和全量是**两个需求**，不是同一份文件的两个版本。这条原来写的是
  「主线一页纸，全量进 JSON」——执行下来，md 里承诺「tier: direct + at: main.js:66
  → 跳过去看三行」，那一行却只在 JSON 里有，人读的 md 只有一条 via 摘要。
  那是拿「短」换「看得见」，不划算。
- **软档不分「可信 / 不可信」两段，分三段**：`full`（跳数和经过都记下来了，
  能复现这条链）、`locate_only`（有位置能跳过去看，链路没记全）、`name_only`
  （只有 API 名，连位置都没有）。硬档也有这三段，只是绝大多数是 `full`。
  理由是「不可信」不是二值的——一条 `full` 的软档和一条 `name_only` 的软档，
  复核成本差一个量级。
- **怎么守**：md 的 sink 表格条目数必须等于 JSON 的 `channel_sink_evidence`
  条目数（`selfcheck` 里已有这条）。摘要模式做出来之后，它的计数还必须和全量一致
  ——**摘要不许自己再算一遍**。
- **缺口（诚实写在这）**：`--summary` 还没做。现在只有全量，没有一页纸那一层。
  想快速看的人只能自己滚 492 行。

## I5 · 以上四条自己进自检，违反即 CI 红

- **是什么**：I1–I4 的守卫都活在 `scripts/selfcheck.py` 里，`scripts/verify.sh`
  调用它，CI 跑它。谁改坏一条，红的是 CI，不是作者的手。
- **为什么**：没有这一条，上面四条又变回自觉。自检的红，是比记忆可靠的东西。
- **怎么守**：selfcheck 里 `check_invariants()` 逐条跑 I1、I2（和 I3 的抽查），
  任何一条失败都计入 `ok` 的与运算，最终让 `verify.sh` 的「基线闸门」红。
