# ADR：用局部子图查询替代深度遍历（opt-in，增量）

**状态**：第一步已完成，主链路未切换
**日期**：2026-11-14
**决策**：不引 joern / CodeQL，自建「通道相关的局部子图」，在子图上做可达查询。

## 为什么要动

现有 L1–L3 解决的是同一个文件里的数据流。跨文件只能靠 `interproc_taint` 一层层
爬调用栈，而爬的层数必须锁一个上限——实测 depth=3 相对 depth=2 耗时 +67%、
结果零变化，于是锁在 2。

问题不在于深度设得小，在于**遍历模型本身**：沿调用栈爬的时候，跨文件、回调、
循环里的数据流天然爬不全，而任何锁定的深度都同时漏两种东西——

- 链长于上限的（假阴）；
- 链里绕路的（噪音，因为爬的时候不看路径上有没有校验）。

## 谁建图：自建，不引外部引擎

| 路线 | 判定 |
| --- | --- |
| joern（js2cpg） | JVM 依赖 + 对 webpack 压缩产物的建图质量未知，破坏零依赖 |
| CodeQL | 引擎闭源、查询语言受限，且产出受其授权约束 |
| **自建轻量 CFG + def-use** | 唯一不破坏零依赖的路线，产出归自己 |

不引外部引擎的另一个理由是**范围可控**：不需要全局 CPG，只需要「通道相关的子图」——
从 `ipcMain.on/handle` 出发，把它涉及的 handler、被调函数、模块依赖、def-use
收集成局部图。对 obsidian 这是几十个函数，不是 3.9 MB 全量。

## 第一步做了什么（已完成）

`jssem.subgraph_summaries(tokens, defs, roots)`：

1. **轻扫**：只找每个函数体里的调用点，建调用边（不跑数据流）；
2. **重扫**：从 roots 沿边 BFS 拿可达集，只对可达集跑 `flows_into_danger`；
3. **组合**：在可达集内部迭代拼摘要到不动点。

关键点：roots 常常是**内联 handler**，不在 `function_defs` 里，所以 BFS 起点
要从 handler 体内找调用目标，不能拿 handler 自己去查表。

### 验证一：能走多深（合成用例）

五层链 `handler → a → b → c → d → writeFileSync`：

| 做法 | 命中 |
| --- | --- |
| 递归 depth=2 | **0**（漏） |
| 递归 depth=3 | **0**（还是漏） |
| 递归 depth=4 | 1 |
| 子图查询 | **1**（不设深度参数） |

### 验证二：复现现有命中（真包，diff 必须为 0）

| 包 | 老口径通道 | 子图通道 | 文件级 diff |
| --- | --- | --- | --- |
| obsidian | 0 | 0 | **0** |

样本薄（真包上 L3 本来就几乎不命中），所以这一轮的证据主要是合成用例。

### 验证三：共用函数不连坐

两个 handler 调不同工具函数，只有碰危险接口的那个被报出来。

## 三个风险（写在这里，不写在事后）

### 1. 压缩产物的 CFG 失真度是最大未知数

webpack 产物一行几十万字符，函数边界靠 tokenizer 恢复，`eval`、动态 require、
字符串拼接模块加载都会让调用边断掉。

**缓解**：先拿 obsidian 的子图做实验，量「边覆盖率」再决定规模，别一上来全局。
现在只做到「调用边」，控制边和数据边还没建。

### 2. 图查询的调试难度比遍历高一档

遍历错了是「少一条」，图错了是「环、误连、爆炸」。

**缓解**：图构建带不变量断言——每个 sink 路径必须有源、每条边两端节点必须存在。
BFS 靠 `visited` 防环，摘要组合按轮数封顶。

### 3. 措辞纪律：图口径不是「确认」

图查询天然像在「下结论」（可达 = 判定）。

**缓解**：图口径产出仍然分层，叫 `graph_confirmed` 而不是 `confirmed`。
`refutes_if` 照写——图的 `refutes_if` 是「这条边可能是假的」，因为压缩产物会断边、
也可能误连。
