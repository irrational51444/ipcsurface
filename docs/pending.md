每条都写了「为什么它排在前面」和「怎么算做完」。

## 1. 那条高危还没报给厂商

**是什么**：`private/audit-aclos.md` 里两条通道的完整利用链——任意路径删除、
任意读 + 任意 URL 上传。文件已经从公开仓库移走（`.gitignore` 里有 `private/`），
但 **git 历史里那三个提交还带着完整内容**。

**为什么排第一**：这是唯一一条有现实后果的。在看雪发帖之前必须先做——
帖子一发，流量进来，仓库被翻，历史也就被翻了。

**怎么算做完**：拿到厂商的受理编号，把编号写进 `private/audit-aclos.md` 抬头。
在那之前，这件事在「未完成」里，不在「已处理」里。

## 2. probe 还没接成第二路

**是什么**：现在的「两路」是名字级 + 语法树级。它们共享同一个 tokenizer、
同一张危险 API 名单、同一批静态盲区（动态注册、运行时拼名、加密 payload、
`eval` 里的代码）。**高度相关，第二遍不带来独立信息。**

`probe_align` 有，但只在靶场上跑；真包静态报 0 的时候不会触发任何提醒。

**为什么排第二**：这是「不漏」这个目标的根本缺口。工具现在能给的最好答案
是「这一层没走到」，而不是「这里没有」——只有运行时探针能把它变成后者。

**怎么算做完**：静态报 0 的包/通道，自动要求一次 probe 对齐；对齐率不达标时
报告升级提醒。不是「有 probe 这个功能」，是「静态的空白被探针补上」。

## 3. `Function（—）` 的证据缺失

**是什么**：dsh 那个包的报告里，有 7 条 `Function`，档位列是 `—`。
`Function` 在危险名单里，被收集了，但 `channel_sink_evidence` 里找不到对应条目。

**为什么排第三**：报告里出现了**无法追溯的条目**。这个工具的全部价值就是
「每条结论都能追问到位置」，出现一条问不下去的，就是自己拆自己的台。

**怎么算做完**：要么补上证据（哪个文件、哪个偏移、怎么到的），要么把它从
「连到危险 API」里拿掉并说明原因。不能就这么挂着。

## 4. git 历史里的那三个提交

**是什么**：`de32779`、`4b95c63`、`0bf29c4` 三个提交里有完整的利用链。

**为什么排第四**：重写历史会破坏已有的 fork 和外部链接。这是个取舍，

**怎么算做完**：要么重写并公告，要么明确接受「历史里就是有」并写进

## 长期项（不影响对外，但影响可信度）

- **只有 Windows 侧的样本。** 十二个包里没有一个是 macOS 或 Linux 的。
  平台差异（路径分隔符、`process.platform` 分支）会让一部分通道扫不到。
- **没有上下文敏感分析。** 同一个函数在不同调用点后果不同，现在一律按
  「handler 里连到了」处理。
- **精扫没有 per-channel 的端口归属。** 只按通道报 `send/invoke`，不说
  这条通道具体从哪个 preload 端口出去的。
- **`unresolved` 在真包上几乎没触发过。** 十二个包里只出现过一次（ES5 原型
  那个）。机制在，但覆盖面没被真实数据压过。

## 2026-11-16 补记：爸爸列的六条已知边界，逐条评过

### 能做，最划算

**漏报原因里名单定了但还没接数据的那些。** `member-call-unresolved`、
`lexer-unrecognized-char`、`unterminated-template-string`、`non-ascii-number`、
`launcher-blocked-attach`、`non-main-process`——名字在词表里，数据源没接，
现在一律报 0。**报 0 不代表没发生。**

这条便宜，而且直接消掉「报了 0 但根本没测」这种半成品状态。开工先动它。

### 能做，收益最大

**跨模块取成员的对象形状分析。** 模块表里「跨模块取成员解出 0/28」那一格就是缺口。
`e.exports = a` 之后再 `a.X`，现在解不出来。打包产物里的通道名和危险 API
大量藏在这个地方。

### 只能做保守版

**别名消歧。** 压缩产物里 `f`/`y`/`m` 同名多义，现在大量标 `ambiguous`。
真解要 SSA 或作用域图；先按参数个数、调用点数量做启发式，**判不准就还标
ambiguous**。宁可多标一次，也不猜——猜错就是错报，错报比漏报好一点，但也不能当成结论卖。

### 已经在做

**native 模块。** 报告里已经写了「导入表读不出来是『读不到』，不是『没有危险导入』」。
这是诚实，不是解决。要往前一步得真去读 PE 导入表。

### 不建议现在动

**堆建模、跨请求生命周期。** 模块级字段的写-读已经在同一个函数体里做了；
跨请求要的是全局状态图。那不是补一个函数，是会写出一堆自己看不懂的东西的活。
排在最后。

### 超出通用静态分析范畴的

**给 @electron/remote 这类转发壳做跨包语义建模。** 能做，但那是「针对已知框架的
特例」，不是通用能力。做之前要想清楚：这是工具该干的，还是应该单独一个规则包。
