# sanitizer 建模：只认三种朴素形态，其余一律不认

## 判定口径

在 handler 的函数体里找校验点，只认能从 token 流上确定读出来的三种：

| 形态 | 长相 | 语义 |
| --- | --- | --- |
| `reject` | `if (COND) return; … sink …` | 校验失败就退出，sink 在块外 |
| `allow` | `if (COND) { … sink … }` | 校验是进入 sink 的前置条件 |
| `guard` | `if (COND) { … } … sink …` | 条件里有校验，但 sink 不在块内，**前置性未定** |
| `allow-ternary` | `COND ? … sink … : …` | 同 allow，写成三元 |

`COND` 必须**像校验**才算：包含比较运算、`typeof`、存在性（`existsSync` 一类）、
字符串方法（`startsWith`、`endsWith`、`includes`）。

`if (p)` 这种裸判断**不算**——那只是分支。

`target` 是条件里第一个被引用的形参。条件里没有形参（比如 `if (S.ready)`）就记 `None`，
那说明这段校验拦的不是参数，是状态。

## refutes_if（固定措辞，不许改）

**没检出校验不等于没有校验。**

校验可能写在 helper 里、跨文件、包在 Promise 链里、写在 try/catch 的 catch 分支、
或者用更绕的表达式（`!==` 套 `&&` 再套函数返回值）。这几种上面一个都不认。

所以 sanitizer 的结论只有三态，没有「安全」：

| 结论 | 含义 |
| --- | --- |
| 有校验 | 在检出的形态里找到了必经的守门人 |
| 疑似可利用 | 存在不经过任何 sanitizer 的路径（要给出那条路径） |
| 无法判定 | 图不确定，或者校验写在我们认不出的形态里 |

第三态必须存在。任何把它压成二选一的改动，都是替人下「安全」结论。
