# 候选分类器：像通道名，还是像噪音

`harvested` 里的候选是一堆「长得像通道的字符串」。真实应用里能有几百个（Obsidian
394 个），全看一遍不现实。以前按机械事实分四档（channel / near-ipc / clustered /
stray）；这里再往前一步：给每个候选 0~1 的可解释得分，并说清凭什么。

## 为什么不训练黑盒模型

两个原因：

1. **零依赖**。项目不引 ML 库，也不该为了一个分类器破这条。
2. **判断要能复核**。黑盒给一个数，读的人不知道对不对；给「和通道名重合 +0.55、
   形态像通道名 +0.15」这种理由，他能自己判断该不该信。

所以这是一个**加权特征 + 可解释理由**的分类器，权重是人工先验，用 golden 数据
校准准确率——脚本只报数，不自动改权重。

## 特征和权重

| 特征 | 权重 | 依据 |
| --- | --- | --- |
| 和静态通道名重合 | +0.55 | 最硬：两边独立看到同一个名字 |
| 在含 `ipcMain`/`ipcRenderer`/`contextBridge` 的文件里 | +0.20 | 名字躺在注册表旁边 |
| 紧挨调用点 | +0.15 | 还没接进统计，先留位 |
| 同前缀成簇（≥3） | +0.10 | 像一张名字表 |
| 形态像通道名（无空格/分号/括号/引号/尖括号，长度 2~200） | +0.15 | 通道名的典型字符形态 |
| 形态像代码片段 | -0.40 | 空格、分号、括号这些基本不是通道名 |

得分截到 0~1。阈值 **0.5** 以上算「像通道」，以下算「像噪音」。

## 实测（6 个真包，2026-11-12）

```
| 包 | 正样本 | 负样本 | 正样本均分 | 负样本均分 |
| obsidian | 0 | 394 | — | 0.31 |
| dsh | 41 | 180 | 0.70 | 0.21 |
| douyin | 0 | 14 | — | 0.21 |
| bilibili | 0 | 91 | — | 0.20 |
| vivo | 0 | 78 | — | 0.30 |
| aclos | 1 | 142 | 0.70 | 0.28 |

阈值 0.5：正样本判对 1.0，负样本判对 1.0
```

正样本（人工核对过的通道名）全部 ≥ 0.5，噪音全部 < 0.5。**但这只说明「形态 +
上下文」这两个特征在这批样本上够用**：

- 正样本只有 42 条（dsh 41 + aclos 1），少；
- 负样本是「非通道名」的候选，里可能有真通道没被人工核（所以「判对 1.0」偏乐观）。

## 边界（诚实清单）

1. **只看形态，不猜语义**。叫 `abc` 的噪音和叫 `abc` 的真通道，形态一样，分不开——
   要靠「和静态通道名重合」这条救。
2. **权重是手工先验**，没有做真正的拟合。想更准，得补正负样本再调（超过一批真包
   才值得做）。
3. **阈值 0.5 是从这批样本拍的**，不是最优解。样本变了要重拍。

## 怎么用

```bash
python scripts/harvest_classifier.py                 # 用 tests/golden/real_packages.json 的真包
python scripts/harvest_classifier.py <x.asar>        # 只跑一个包（没有人工标注，只能看负样本均分）
```
